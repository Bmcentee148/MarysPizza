# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Static marketing site for Mary's Pizza and Pasta (three locations: Speonk, Islip Terrace, Farmingdale, NY). Hand-written HTML + CSS + vanilla JS, assembled by two small Python 3 scripts (standard library only, no npm, no framework). Deployed on Netlify, which runs the build on every push (`netlify.toml`) and publishes `dist/`. The inquiry form relies on Netlify Forms.

Pages: homepage `/`, three menu pages (`/takeout-menu-speonk/`, `/takeout-menu-farmingdale-islip/`, `/catering-menu/`), `/gallery/`, `/promotions/` and `/contact/` (the inquiry form). Instagram is `https://www.instagram.com/maryspizzapastany/` (footer icon, gallery band, promotions); the footer Facebook icon is still a `#` placeholder.

## Commands

```bash
cd src && python3 build.py          # build into dist/ (also runs make_pages.py); fails on any check
cd dist && python3 -m http.server 8000   # preview at http://localhost:8000/
```

There are no tests or linter; the build's checks are the validation. Pages use root-relative URLs, so open them through a server, not via `file://`. Form submission only works when deployed on Netlify.

## How the build works

- `src/index.html` is the homepage **and** the master template. Everything before `<main id="main">` (the `<head>` with all site CSS in one `<style>`, header/nav, mobile menu) and everything after `</main>` (footer, shared JS) is shared by every page. Edit the header/footer/site CSS only here.
- `src/pages/<name>.main.html` holds only the `<main>` content of an inner page. Page-specific CSS/JS lives next to it (`menu.css` for the three menu pages, `gallery.css`/`.js`, `contact.css`, `promotions.css`/`.js`) and is listed in that page's `PAGES` entry: `css` files are inlined at the end of the site `<style>`, `js` files before `</body>`.
- `src/make_pages.py` (step 1): `PAGES` dict (title, meta description, optional `css`/`js` files from `pages/`). Stitches HEAD + content + FOOT into `src/<name>.html` (git-ignored), swapping title, description and canonical via `must_replace` helpers that assert exactly one match, so a template change that breaks a replacement fails the build.
- `src/build.py` (step 2): wipes `dist/`, copies `src/assets/`, runs step 1, fills `TEXT` placeholders (`__ORDER_URL__` etc.; values containing `TODO` print a NOTE), validates, then writes clean URLs (`dist/<name>/index.html`, served at `/<name>/`) and `dist/sitemap.xml`. The production domain lives only in the homepage canonical.
- The build **fails** on: unreplaced `__TOKEN__`; relative links or links to `.html` (use `/page/`, `/#section`, `/assets/...`); links to pages not in `PAGES` (or `PLANNED`); `#fragment` links to ids that don't exist on the target page; missing/mis-capitalized asset files; inline `data:` images; wrong canonical; `<img>` without alt; `target="_blank"` without `rel="noopener"`; the Netlify form on `/contact/` losing `data-netlify` or its hidden `form-name` input; a promotion's `data-ends` that isn't a `YYYY-MM-DD` date. `href="#"` placeholders (social icons) and expired promotions only print a NOTE.
- To add a page: create `src/pages/<name>.main.html` and add it to `PAGES` in `make_pages.py`. Old `.html` URLs of the menu pages are 301-redirected in `netlify.toml`; keep that if pages are renamed.
- Images live in `src/assets/images/` and are linked by root-relative path (`/assets/images/logo.png`), including the hero `url()` in the CSS. Don't inline images as base64. `TempPics/` holds unused source photos.
- Logos: the header uses `logo-horizontal.webp` (emblem plus "Mary's Pizza & Pasta" text, transparent background, 612×200, shown 58px tall / 48px scrolled, 70px / 56px from 1200px up, 44px on phones). Its text is dark, so it only works on light backgrounds; the footer and the homepage catering and private events panels use the round emblem `logo.png`, and the hero uses `hero-badge.png`.
- **Gallery** (`/gallery/`, `src/pages/gallery.main.html`): photos live in `src/assets/images/gallery/food/` and `.../restaurant/` (unused photos may sit there too; only the ones linked in the page are shown). Each tile is `<a class="g-item" href="<image>" data-cat="food|restaurant"><img ... alt width height loading="lazy"></a>`; the alt text doubles as the caption in the full-screen viewer. To add photos: resize to max 1600px on the long side, save as WebP (~quality 80) with metadata stripped (Pillow is available), add a tile, and keep the order mixed so no grid column is all food or all restaurant. Don't commit raw phone photos to the repo.
- **Promotions** (`/promotions/`, `src/pages/promotions.main.html`): one `<article class="promo-card" data-ends="YYYY-MM-DD">` per promo, with the flyer image linking to itself, the offer written out as text (prices, dates, fine print; keeps it readable by search engines and screen readers), and a "Download the Flyer" link. Flyer files go in `src/assets/promotions/`: the original PDF plus a WebP rendered from it (`pdftoppm -r 200 -png`, then max 1400px long side, WebP ~quality 82). `promotions.js` hides a card in the visitor's browser after its `data-ends` day (local midnight), so promos drop off on time without a rebuild; when none are left, `#promoEmpty` ("No promotions running right now" + Instagram) shows. The build prints a NOTE for each expired promo; delete those cards (and their asset files) since the hidden text is still in the HTML.

## Shared JS (in `src/index.html`, runs on every page)

- **Location switcher**: the `LOCATIONS` object (id → name, `orderUrl`, `takeoutMenuUrl`, `cateringMenuUrl`) drives everything location-specific. `applyLocation(id)` syncs the nav/mobile `<select>`s, all `.order-link` hrefs, `.loc-name` text, `.loc-pill`/`.loc-card` active states and `#takeoutMenuLink`/`#cateringMenuLink`, then persists to `localStorage` key `marysLocation` (so the choice carries across pages). `DEFAULT_LOC` is `farmingdale`. On a takeout menu page (a page whose path is some location's `takeoutMenuUrl`), the page decides the location: on load the picker is set to match the menu shown, and picking a location whose takeout menu is a different page navigates there (`pickLocation`); the catering page and homepage never navigate. To add a location, update `LOCATIONS` plus the matching `data-loc` elements and `<option>`s.
- **Anchor scrolling**: links whose URL points to an id on the current page (`/#menu` on the homepage) are intercepted and scrolled with an offset for the sticky nav (`scrollToId`); from inner pages they navigate to the homepage, where a load-time hash fix applies the same offset. Don't rely on native anchor jumps or CSS `scroll-margin` alone.
- **Inquiry form** (`#inqForm`, on `/contact/` only, guarded with `if(form)`): Netlify form `inquiry` with honeypot `bot-field`, AJAX `fetch('/')` url-encoded. On a 2xx response `#formHost` gets `is-sent` (thank-you with all three phone numbers); on a network error or non-2xx response `#formError` is shown with the phone numbers and the typed fields are kept, and the submit button reads "Sending..." while in flight. `/contact/?type=catering` or `?type=event` preselects the inquiry type (catering buttons on the homepage and catering menu, and the private events "Send Us the Details" button use these). The homepage only has a `.contact-band` linking to `/contact/`. Netlify detects the form from the built HTML, so keep `data-netlify`, the hidden `form-name` input and field `name`s.
- **Header nav and breakpoints**: the header nav and ☰ menu are Menu · Promotions · Gallery · Locations · Contact (Catering and Private Events are only in the footer and on the homepage). Below 1024px the nav links and location picker are hidden and the ☰ burger opens `#mobileMenu` (which has its own location picker, `#locSwitcherMobile`); the rest of the phone layout is the `max-width:720px` media query. From 1200px up the header content is wider than the page (`.nav-inner` max 1440px, 40px side padding) and the nav links are bigger (1.06rem, 36px apart; these rules use `header.nav .nav-links` so they beat the base rules defined later) while the sections below stay at `--maxw` (1160px). The header fits at 1024px with only ~28px to spare and the logo image can't shrink or wrap, so adding a nav link will likely overflow: check `.nav-inner` has no overflow at 1024px, and move the ☰ breakpoint up or drop a link if it does. New links go in the header nav and the mobile menu (and the footer if wanted).
- The header is `position:sticky` and gets `.scrolled` (smaller padding and logo) once the page scrolls. `html`/`body` use `overflow-x:clip` to stop sideways scrolling; never change that to `overflow-x:hidden`, which silently breaks the sticky header.
- Code that only applies to some pages must tolerate its elements being absent. `.reveal` elements fade in via IntersectionObserver (adds `.in`).
