# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Static marketing site for Mary's Pizza and Pasta (three locations: Speonk, Islip Terrace, Farmingdale, NY). Hand-written HTML + CSS + vanilla JS, assembled by two small Python 3 scripts (standard library only, no npm, no framework). Deployed on Netlify, which runs the build on every push (`netlify.toml`) and publishes `dist/`. The inquiry form relies on Netlify Forms.

Pages: homepage `/`, six menu pages: takeout (`/takeout-menu-speonk/`, `/takeout-menu-farmingdale-islip/`, shared by those two stores), dine-in (`/dine-in-menu-speonk/`, `/dine-in-menu-farmingdale/`, `/dine-in-menu-islip-terrace/`: one per store, each with its own items, prices and drinks, transcribed from the printed menus; Speonk's has a Food and a Drinks part (`.menu-part` heading, jump links) for its full bar and wine list, with wine vintages left out because they change; updated from photos of the current printed menu in November 2026) and `/catering-menu/`, `/gallery/`, `/promotions/`, `/contact/` (the inquiry form), the location page `/speonk/`, and a 404 page. `/islip-terrace/` and `/farmingdale/` are planned location pages (in `PLANNED`, so links to them pass the build; they show the 404 page until built). Instagram is `https://www.instagram.com/maryspizzapastany/` (footer icon, gallery band, promotions); the footer Facebook icon is still a `#` placeholder.

Location facts (keep copy accurate): Speonk is in the old Olde Speonk Inn on Montauk Highway, has a full bar that people really sit at, a patio and a private room. Islip Terrace has a full bar (liquor), but it's mostly a service bar for the tables, not a hangout. Farmingdale serves beer and wine only. Reservations: Speonk and Islip Terrace on OpenTable, Farmingdale by phone only. All three use the same HungerRush online ordering link.

The old WordPress site is still live on the production domain and has ~40 pages (location pages like `/home-speonk/`, `/home-islip/`, `/home-farmingdale/`, plus old menu, dine-in menu, drink menu, contact and employment pages). `netlify.toml` already has 301 redirects for all of them (49 rules: location pages to the new location pages, the rest to their closest match; junk pages like the theme demo, "Hello world!" post and wp-login deliberately have none and get the 404 page). The rules for `/islip-terrace/` and `/farmingdale/` are in place before those pages exist, so the domain must not move until both are built. The full crawl and mapping are in `redirect-plan.md` (visual version: `redirect-chart.html`). Redirect targets have no `#fragment` (Netlify may not keep it).

## Commands

```bash
cd src && python3 build.py          # build into dist/ (also runs make_pages.py); fails on any check
cd dist && python3 -m http.server 8000   # preview at http://localhost:8000/
```

There are no tests or linter; the build's checks are the validation. Pages use root-relative URLs, so open them through a server, not via `file://`. Form submission only works when deployed on Netlify.

## How the build works

- `src/index.html` is the homepage **and** the master template. Everything before `<main id="main">` (the `<head>` with all site CSS in one `<style>`, header/nav, mobile menu) and everything after `</main>` (footer, shared JS) is shared by every page. Edit the header/footer/site CSS only here.
- `src/pages/<name>.main.html` holds only the `<main>` content of an inner page. Page-specific CSS/JS lives next to it (`menu.css` for the menu pages, `gallery.css`/`.js`, `contact.css`, `promotions.css`/`.js`, `location.css` for location pages, `404.css`) and is listed in that page's `PAGES` entry: `css` files are inlined at the end of the site `<style>`, `js` files before `</body>`.
- `src/make_pages.py` (step 1): `PAGES` dict (title, meta description, optional `css`/`js` files from `pages/`, optional `noindex`). Stitches HEAD + content + FOOT into `src/<name>.html` (git-ignored), swapping title, description and canonical via `must_replace` helpers that assert exactly one match, so a template change that breaks a replacement fails the build.
- `src/build.py` (step 2): wipes `dist/`, copies `src/assets/`, runs step 1, fills `TEXT` placeholders (`__ORDER_URL__`, `__RESERVE_SPEONK__`, `__RESERVE_ISLIP__` (the OpenTable links); values containing `TODO` print a NOTE) and `__SITE_URL__` (the production domain from the homepage canonical, for absolute URLs in structured data), validates, then writes clean URLs (`dist/<name>/index.html`, served at `/<name>/`) and `dist/sitemap.xml`. The production domain lives only in the homepage canonical.
- A page with `"noindex": True` in `PAGES` (the 404 page) gets `<meta name="robots" content="noindex">` instead of a canonical and is left out of the sitemap. `404` is written to `dist/404.html`, which Netlify serves for any missing URL; its links are root-relative, so they work from any path.
- The build **fails** on: unreplaced `__TOKEN__`; relative links or links to `.html` (use `/page/`, `/#section`, `/assets/...`); links to pages not in `PAGES` (or `PLANNED`); `#fragment` links to ids that don't exist on the target page; missing/mis-capitalized asset files; inline `data:` images; wrong canonical; `<img>` without alt; `target="_blank"` without `rel="noopener"`; the Netlify form on `/contact/` losing `data-netlify` or its hidden `form-name` input; a promotion's `data-ends` that isn't a `YYYY-MM-DD` date; a `netlify.toml` redirect whose target isn't a built or `PLANNED` page, has a `#fragment`, or whose source is a page that exists (Netlify would serve the page instead), or a source redirected twice. `href="#"` placeholders (social icons) and expired promotions only print a NOTE.
- To add a page: create `src/pages/<name>.main.html` and add it to `PAGES` in `make_pages.py`. The site isn't live on the real domain yet, so pages can be renamed freely (only the site's own links and `LOCATIONS` need updating); once it is live, a rename needs a 301 in `netlify.toml`. Renaming a page that's a redirect target also means updating its rules, or the build fails.
- Images live in `src/assets/images/` and are linked by root-relative path (`/assets/images/logo.png`), including the hero `url()` in the CSS. Don't inline images as base64. `TempPics/` holds unused source photos.
- Logos: the header and the top of the phone menu (`.mm-logo`) use `logo-horizontal.webp` (emblem plus "Mary's Pizza & Pasta" text, transparent background, 612×200, shown 58px tall / 48px scrolled, 70px / 56px from 1200px up, 44px on phones). Its text is dark, so it only works on light backgrounds; the footer and the homepage catering panel use the round emblem `logo.png`, and the hero uses `hero-badge.png`. The homepage private events panel uses a photo instead (`private-event-room.webp`, `.art.art-photo`: the image fills the panel via `object-fit:cover`; the same class works for any `.feature` panel).
- **Gallery** (`/gallery/`, `src/pages/gallery.main.html`): photos live in `src/assets/images/gallery/food/` and `.../restaurant/` (unused photos may sit there too; only the ones linked in the page are shown). Each tile is `<a class="g-item" href="<image>" data-cat="food|restaurant"><img ... alt width height loading="lazy"></a>`; the alt text doubles as the caption in the full-screen viewer. To add photos: resize to max 1600px on the long side, save as WebP (~quality 80) with metadata stripped (Pillow is available), add a tile, and keep the order mixed so no grid column is all food or all restaurant. Don't commit raw phone photos to the repo.
- **Promotions** (`/promotions/`, `src/pages/promotions.main.html`): one `<article class="promo-card" data-ends="YYYY-MM-DD">` per promo, with the flyer image linking to itself, the offer written out as text (prices, dates, fine print; keeps it readable by search engines and screen readers), and a "Download the Flyer" link. Flyer files go in `src/assets/promotions/`: the original PDF plus a WebP rendered from it (`pdftoppm -r 200 -png`, then max 1400px long side, WebP ~quality 82). `promotions.js` hides a card in the visitor's browser after its `data-ends` day (local midnight), so promos drop off on time without a rebuild; when none are left, `#promoEmpty` ("No promotions running right now" + Instagram) shows. The build prints a NOTE for each expired promo; delete those cards (and their asset files) since the hidden text is still in the HTML. The exception is `#weekly-specials` (`.promo-card--text`): Chicken Night and Seafood Night at Farmingdale and Islip Terrace only (Speonk has no weekly specials). It has no `data-ends` (always shown) and no flyer, by choice: the old site linked so many menus that the specials are only summarized here, with the full menus kept in the stores.
- **Location pages** (`/speonk/`, `src/pages/speonk.main.html`, styles in `location.css`): hero with Reserve a Table + Order Online, a Visit us card (address, phone, hours, directions) beside an embedded Google map, an about section with store-specific copy and features, photos, menus, and links to the other locations. Each starts with a `Restaurant` JSON-LD block (address, phone, hours, menu, reservations; URLs use `__SITE_URL__`). The hero section has `data-page-loc="<id>"`, which makes the location picker start on that location. To add Islip Terrace or Farmingdale: copy the Speonk page with that store's details and real store-specific copy (Google penalizes near-duplicate pages), add it to `PAGES` with `css: ["location.css"]`, and remove its URL from `PLANNED` in `build.py`.

## Shared JS (in `src/index.html`, runs on every page)

- **Location switcher**: the `LOCATIONS` object (id → name, `orderUrl`, `takeoutMenuUrl`, `dineInMenuUrl` (may be `null` for a location without a dine-in page), `cateringMenuUrl`) drives everything location-specific. `applyLocation(id)` syncs the nav/mobile `<select>`s, all `.order-link` hrefs, `.loc-name` text, `.loc-pill`/`.loc-card` active states and `#dineInMenuLink`/`#takeoutMenuLink`/`#cateringMenuLink` (the homepage menu cards; the Dine-In card is hidden for a location without a dine-in page, and the card grid reflows to two), then persists to `localStorage` key `marysLocation` (so the choice carries across pages). `DEFAULT_LOC` is `farmingdale`. On a takeout or dine-in menu page (a page whose path is some location's `takeoutMenuUrl` or `dineInMenuUrl`), the page decides the location: on load the picker is set to match the menu shown, and picking a location whose menu of that kind is a different page navigates there, or to its takeout menu if it has no dine-in page (`pickLocation`); the catering page and homepage never navigate. To add a location, update `LOCATIONS` plus the matching `data-loc` elements and `<option>`s.
- **Anchor scrolling**: links whose URL points to an id on the current page (`/#menu` on the homepage) are intercepted and scrolled with an offset for the sticky nav (`scrollToId`); from inner pages they navigate to the homepage, where a load-time hash fix applies the same offset. Don't rely on native anchor jumps or CSS `scroll-margin` alone.
- **Inquiry form** (`#inqForm`, on `/contact/` only, guarded with `if(form)`): Netlify form `inquiry` with honeypot `bot-field`, AJAX `fetch('/')` url-encoded. On a 2xx response `#formHost` gets `is-sent` (thank-you with all three phone numbers); on a network error or non-2xx response `#formError` is shown with the phone numbers and the typed fields are kept, and the submit button reads "Sending..." while in flight. `/contact/?type=catering`, `?type=event`, `?type=employment` or `?type=review` preselects the inquiry type (catering buttons on the homepage and catering menu, and the private events "Send Us the Details" button use the first two; the old site's employment page will redirect to `?type=employment`). The Employment type is how job seekers reach the stores (there's no jobs page); choosing it switches the Details placeholder to ask for the position, experience and availability. The Review type is for private complaints and feedback about a visit (deliberately not called "complaint"); choosing it switches the Details placeholder to "Which location, when you visited, and what happened." The homepage only has a `.contact-band` linking to `/contact/`. Netlify detects the form from the built HTML, so keep `data-netlify`, the hidden `form-name` input and field `name`s.
- **Header nav and breakpoints**: the header nav and ☰ menu are Menu · Promotions · Gallery · Locations · Contact (Catering and Private Events are only in the footer and on the homepage). Locations is a `.nav-drop`: the link still goes to `/#locations`, and a dropdown (`.nav-drop-menu`, opened by `:hover` and `:focus-within`, no JS) lists `/speonk/`, `/islip-terrace/` and `/farmingdale/`. The ☰ menu lists the same three under "Locations & Hours" (`.mm-sub`). Below 1024px the nav links and location picker are hidden and the ☰ burger opens `#mobileMenu` (which has its own location picker, `#locSwitcherMobile`); the rest of the phone layout is the `max-width:720px` media query. From 1200px up the header content is wider than the page (`.nav-inner` max 1440px, 40px side padding) and the nav links are bigger (1.06rem, 36px apart; these rules use `header.nav .nav-links` so they beat the base rules defined later) while the sections below stay at `--maxw` (1160px). The header fits at 1024px with only ~10px to spare and the logo image can't shrink or wrap, so adding a nav link will likely overflow: check `.nav-inner` has no overflow at 1024px, and move the ☰ breakpoint up or drop a link if it does. New links go in the header nav and the mobile menu (and the footer if wanted).
- **Announcement bars** (`.announce`, in `src/index.html` just above the nav, so they show on every page): short promos, each with a long and a short (phone) version of the text and a Details link straight to its promo card (`/promotions/#<card id>`; every promo card has an `id`). They all start `hidden`; the shared JS shows the **first** bar whose `data-bar-starts`/`data-bar-ends` (inclusive, Long Island time) include today and that the visitor hasn't closed during this visit (`sessionStorage` key `marysBarClosed:<data-bar-id>`: closing lasts across pages and refreshes, and the bar comes back on their next visit). To queue the next promo, add a bar after the current one with a later start date and a new `data-bar-id`. The build checks the dates and prints a NOTE once a bar has expired.
- The header is `position:sticky` and gets `.scrolled` (smaller padding and logo) once the page scrolls. `html`/`body` use `overflow-x:clip` to stop sideways scrolling; never change that to `overflow-x:hidden`, which silently breaks the sticky header.
- **Reservations** (OpenTable charges per booking, so calling is prioritized): the hero's first button is Reserve a Table, a `<details class="reserve-drop">` whose `.reserve-menu` has one `.rz-row` per location; the ☰ menu has the same rows in `<details class="mm-reserve">`; each homepage location card and the Speonk page hero lead with Call to Reserve, with OpenTable (`__RESERVE_SPEONK__` / `__RESERVE_ISLIP__`) as a small secondary link. Farmingdale is phone only. Hours-aware: any element with `data-rz="<location id>"` gets `.is-closed` from the shared JS (`STORE_HOURS`, Sunday-first `[open, close]` minutes, checked in America/New_York time every minute); inside it, `.rz-if-open` shows while open and `.rz-if-closed` while closed, so after hours Reserve Online leads and calling becomes the fallback. Keep `STORE_HOURS` in sync with the posted hours (it doesn't know holidays). The shared JS closes the hero chooser on an outside click or Escape. It always asks which location rather than following the picker, since first-time visitors default to Farmingdale. On phones the chooser is centered under the button row. The hero uses `overflow:visible; overflow-x:clip` (not `hidden`) so the chooser can open past its bottom edge.
- The homepage location cards highlight the card matching the picked location (`.loc-card.active`, with a "Your location" tag that intentionally pushes that card's content down so it stands out).
- Code that only applies to some pages must tolerate its elements being absent. `.reveal` elements fade in via IntersectionObserver (adds `.in`).
